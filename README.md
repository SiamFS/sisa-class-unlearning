# Machine Unlearning for Class Removal through SISA-based Deep Neural Network Architectures

</div>

An implementation of **class-level** machine unlearning built on a modified SISA
(Sharded, Isolated, Sliced, Aggregated) framework. The original SISA framework of
Bourtoule et al. targets removal of individual **data points**; this implementation
targets removal of an entire **class**, which is the situation organisations actually
face when they must delete every record belonging to a category for privacy
compliance.

---

## How it works

The pipeline departs from vanilla SISA in three structural ways:

1. **Class-isolated sharding** — each shard receives *whole classes* rather than a
   random subset of points, so every shard becomes a specialist over its own classes.
   A load-balancing heuristic keeps shard sizes within a bounded imbalance ratio.
   With `NUM_SHARDS = 2`, CIFAR-10 splits 5 classes per shard.

2. **Class-sequential slicing** — within a shard, slice *k* is filled with one class
   until full before spilling into slice *k+1*. Because a class occupies a contiguous
   run of slices, deleting it only invalidates checkpoints from its **first** slice
   onward; everything before that is reused untouched. This is what makes unlearning
   cheap.

3. **Learned gating instead of aggregation** — a small CNN routes each sample to
   exactly **one** shard, and only that specialist runs. The router predicts a *shard
   index*; it stores no class information.

**Unlearning** removes the class from every slice, finds the first affected slice per
shard, rolls back to that slice's checkpoint (which provably never saw the class),
and replay-retrains forward. Shards that never held the class are not touched at all.

## Prerequisites

- Python 3.9+
- (Optional) An NVIDIA GPU with drivers, for CUDA-accelerated training

## Installation

Run the setup script from the project root. It creates a `.venv`, detects an NVIDIA
GPU via `nvidia-smi`, installs the matching CUDA build of PyTorch (or the CPU-only
build if no GPU is found), then installs the remaining dependencies from
`requirements.txt`.

**Windows (PowerShell):**
```powershell
.\setup.ps1
```
If PowerShell blocks the script with an execution-policy error:
```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

**Linux / macOS:**
```bash
./setup.sh
```

Activate the environment before running anything below:

```powershell
.venv\Scripts\activate          # Windows
```
```bash
source .venv/bin/activate       # Linux / macOS
```

## Where output goes

All generated files are written **inside the repository**, under paths anchored to
`config.REPO_ROOT` (the directory containing `config.py`). The scripts therefore work
from any working directory, and everything they produce is covered by `.gitignore`:

```
sisa-class-unlearning/
├── data/                              downloaded dataset cache (config.DATA_DIR)
└── projects/cifar10_sisa_pytorch/     all run artifacts (config.PROJECTS_DIR / PROJECT_NAME)
    ├── sisa_data/                     shards, slices, test/validation splits, metadata.json
    ├── models/                        per-slice + final shard checkpoints, gating_model.pth
    ├── data_info/                     all figures (confusion matrices, ROC, timings)
    └── training_metrics.json          machine-readable baseline read by the unlearning stage
```

These directories hold hundreds of megabytes and are regenerated by the pipeline, so
they are intentionally not committed.

## Usage

### 1. Data processing

Downloads the dataset, builds the splits, and partitions into shards and slices.

```bash
python data_processing/entry_data_processing.py
```
Optional: `--num-shards N`, `--num-slices N` (default to the `config.py` values).

CIFAR-10's **official test set is held out untouched** (10,000 images, never merged or
reshuffled). Validation is carved out of the official 50,000-image training pool only,
giving 44,000 / 6,000 / 10,000 train / validation / test. Normalisation statistics are
computed from the training split alone and stored in `metadata.json`.

### 2. Training

Trains the gating network first, then each shard incrementally slice by slice.

```bash
python training/entry_training.py
```

Writes per-slice checkpoints (needed for unlearning rollback), a final model per
shard, all figures, and `training_metrics.json`.

> To retrain from scratch, delete `projects/<project>/models/` first — the script
> reuses an existing final shard model if it finds one.

### 3. Unlearning

```bash
# Single class
python unlearning/sisa_unlearning.py --class-name cat

# Several classes at once
python unlearning/sisa_unlearning.py --class-name cat dog ship
```
Optional: `--project-name NAME`, `--model-name NAME`.

Reports data-removal time, retraining time, before/after accuracy, deleted-class
accuracy, and a membership-inference AUC.

### 4. Prediction analysis

Inspects how the current system behaves on a given class.

```bash
python search.py --class-name cat
python search.py --class-name dog --threshold 0.3 --samples 16   # max 16
```

## Verifying that unlearning worked

Two checks run automatically at the end of unlearning:

**Deleted-class accuracy** — compared against a model retrained from scratch without
the class. Such a model still has an output unit for the deleted class, but never
receives it as a training target, so it predicts it ~never. The target is therefore
**~0%**, not `1/num_classes`, and only an upper bound
(`UNLEARNING_DELETED_CLASS_MAX_ACCURACY`) is meaningful.

**Membership inference (MIA)** — a loss-threshold attack that tries to distinguish
deleted-class *training* samples (members) from held-out *test* samples of the same
class (non-members). If the class has genuinely been forgotten, the model treats both
alike and the attack scores **AUC ≈ 0.5**. AUC well above 0.5 means membership is
still detectable, i.e. deletion is incomplete. Groups are balanced and drawn from up
to `MIA_MAX_MEMBER_SAMPLES` members so the estimate is not dominated by small-sample
noise.

## Reproducibility

`config.set_seed()` is called by all three entry points and seeds Python's `random`,
NumPy's global RNG, and torch on CPU and GPU — covering weight initialisation, dropout
masks, augmentation, and replay sampling. `DETERMINISTIC_CUDNN` additionally forces
deterministic cuDNN kernels.

With `RANDOM_SEED = 42` unchanged, repeated runs reproduce bit-identically. Set
`DETERMINISTIC_CUDNN = False` to trade exact reproducibility for speed.

## Configuration

All parameters live in `config.py`. The ones worth knowing:

| Parameter | Meaning |
|---|---|
| `NUM_SHARDS`, `NUM_SLICES_PER_SHARD` | SISA partitioning. `NUM_SHARDS` cannot exceed the class count under class isolation. |
| `BATCH_SIZE`, `MAX_EPOCHS`, `LEARNING_RATE` | Shard-model training. |
| `TRAINING_PATIENCE`, `TRAINING_MIN_DELTA` | Early stopping on validation loss. |
| `GATING_*` | Router training. Defaults mirror the shard-model settings so the two are directly comparable. |
| `REPLAY_RATIO` | Fraction of each batch drawn from the replay buffer (0.3 = 70% new data + 30% replay). |
| `USE_SMART_REPLAY` | `True` uses the importance + temporal-decay buffer; `False` uses uniform random replay. |
| `LABEL_SMOOTHING` / `UNLEARNING_LABEL_SMOOTHING` | Must stay equal, or the before/after comparison is confounded by the objective changing rather than by unlearning. |
| `UNLEARNING_RETRAIN_GATING` | `False` (default) keeps the existing router — it emits shard indices only, and the shards it routes into have already forgotten the class. `True` refits it from the surviving slices, so no component of the ensemble has weights fitted on the deleted images; its cost is added to the reported unlearning time. |
| `CONFIDENCE_THRESHOLD`, `GATING_MARGIN_THRESHOLD` | Routing confidence gates. Predictions below them are returned as `-1` (rejected). |
| `DATASET_NAME`, `SUPPORTED_DATASETS` | Dataset selection. |
| `RANDOM_SEED`, `DETERMINISTIC_CUDNN` | Reproducibility. |

### Using a different dataset

Class count, image size and channel count are all derived from the data at runtime,
so switching datasets is a one-line change:

```python
DATASET_NAME = "CIFAR-100"
```

CIFAR-10 and CIFAR-100 are supported out of the box. To add another, add one entry to
`SUPPORTED_DATASETS` — any torchvision dataset exposing `.data`, `.targets` and
`.classes` will work.
